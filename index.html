Zero-shot

เริ่มต้น

กำหนดแนวคิดหลักของเกมโดยไม่ให้ตัวอย่างโค้ดหรือโครงสร้างระบบ

ช่วยเขียนโค้ดเกม 2D ด้วย HTML, CSS และ JavaScript ให้ผู้เล่นควบคุมตัวละครเพื่อเก็บเหรียญและหลบสิ่งกีดขวาง มีคะแนน มีพลังชีวิต และแสดงข้อความเมื่อชนะหรือแพ้
ผลลัพธ์: ได้ต้นแบบพื้นฐาน แต่รายละเอียด collision และ game state อาจไม่ครบ

Few-shot

พัฒนาแล้ว

เพิ่มตัวอย่างวงจรเกม ชื่อฟังก์ชัน เงื่อนไขชนะ–แพ้ และกรณีทดสอบ

คุณเป็นนักพัฒนาเกมเว็บ สร้างเกม Coin Runner ด้วย Canvas และ JavaScript รูปแบบ: Input → Update → Collision → Render ข้อกำหนด: เหรียญ 5 ชิ้น, ชีวิต 3 หน่วย, คะแนน, Restart
ผลลัพธ์: ได้โค้ดมีโครงสร้าง สถานะเกม และพฤติกรรมที่ทดสอบได้

ตัวอย่างการจัดเนื้อหาแบบบทความหรือหนังสือด้วยโครงสร้างบท, บทคัดย่อ และสมการที่แสดงผลใน HTML ผ่าน MathJax

Game systems note · chapter 01

คณิตศาสตร์เบื้องหลังการเคลื่อนที่ในเกม 2D

บทคัดย่อ. บทความสั้นนี้อธิบายว่าตำแหน่ง ความเร็ว และช่วงเวลาเชื่อมโยงกันอย่างไรใน Game loop และเหตุใดการตรวจการชนจึงสามารถอธิบายด้วยกรอบสี่เหลี่ยมและอสมการได้

1. การเคลื่อนที่ตามเวลา

เมื่อผู้เล่นมีตำแหน่งเริ่มต้น $(x_t,y_t)$ และความเร็ว $(v_x,v_y)$ ตำแหน่งในเฟรมถัดไปคำนวณได้จาก

\[x_{t+1}=x_t+v_x\Delta t,\qquad y_{t+1}=y_t+v_y\Delta t\]

2. เงื่อนไขการชน

วัตถุสองชิ้นชนกันเมื่อกรอบสี่เหลี่ยมของทั้งสองทับซ้อนกันในแกน x และแกน y การอธิบายแบบนี้นำไปเขียนเป็นฟังก์ชัน overlaps() ใน JavaScript ได้

\[x_1<x_2+w_2\;\land\;x_1+w_1>x_2\]

04 — Desmos relationship

อธิบายความสัมพันธ์
ทางคณิตศาสตร์ด้วย DESMOS

เขียนสมการและแสดงกราฟอนุพันธ์ของฟังก์ชัน x² เพื่อเชื่อมโยงความชัน เส้น Secant และเส้น Tangent

DESMOS ACTIVITY

การชี้ความเข้าใจผิดด้วยกราฟ

ถาม: ความชันระหว่าง 2 จุดต่างจากความชัน ณ จุดเดียวอย่างไร?
ตอบ: เส้น Secant เชื่อมสองจุด ส่วนเส้น Tangent เป็นเส้นสัมผัสที่จุดเดียว เมื่อ h เข้าใกล้ศูนย์ ความชันของ Secant จะเข้าใกล้ความชันของ Tangent

สมการที่นำไปสร้างใน Desmos

  • f(x)=x^2 คือกราฟฟังก์ชันหลัก
  • P=(a,f(a)) และ Q=(a+h,f(a+h))
  • m_sec=(f(a+h)-f(a))/h คือความชันเส้น Secant
  • y-f(a)=f'(a)(x-a) คือเส้น Tangent เมื่อ h→0

04 — Reflection by round

เรียนรู้จาก
ผลลัพธ์ทั้ง 1–4

การสะท้อนนี้เปรียบเทียบตั้งแต่การสร้าง Prompt แรก ผลลัพธ์ที่ได้ การถาม–ตอบ และผลลัพธ์ใหม่จาก Few-shot

ครั้งที่ 1

เริ่มจาก Zero-shot

เรียนรู้ว่า AI สร้างต้นแบบเกมได้จากคำสั่งสั้น ๆ แต่ยังมีพื้นที่ให้ตีความมาก จึงยังไม่ควบคุมโครงสร้างและรายละเอียดของระบบได้เต็มที่

ครั้งที่ 2

ประเมินผลลัพธ์แรก

พบว่าต้นแบบมีตัวละคร คะแนน และการควบคุมเบื้องต้น แต่ต้องตรวจ Collision, ขอบเขตหน้าจอ และสถานะชนะ–แพ้ด้วยตนเอง

ครั้งที่ 3

ถาม–ตอบเพื่อพัฒนา Few-shot

เรียนรู้ว่าการระบุเทคโนโลยี Game loop ชื่อฟังก์ชัน กติกา และกรณีทดสอบ ทำให้ความต้องการของระบบชัดเจนขึ้น

ครั้งที่ 4

ได้ผลลัพธ์ใหม่ที่เป็นระบบ

Few-shot ช่วยให้โค้ดมี Input, Update, Collision, Render, Score, Lives, Win/Lose และ Restart ซึ่งนำไปทดสอบและต่อยอดได้ง่ายกว่า

ประเด็นผลลัพธ์แรกจาก Zero-shotผลลัพธ์ใหม่จาก Few-shot
ความชัดเจนระบุแนวคิดเกมโดยรวมระบุเทคโนโลยี โครงสร้าง และกติกา
โครงสร้างโค้ดAI เลือกวิธีจัดโค้ดเองกำหนด Input → Update → Collision → Render
การตรวจสอบต้องทดลองและค้นหาข้อผิดพลาดเองมีกรณีทดสอบการควบคุม การชน คะแนน ชนะ แพ้ และ Restart

ข้อสรุป: Prompt ที่ดีไม่ได้ยาวเพราะใส่รายละเอียดแบบไม่มีเป้าหมาย แต่ชัดเจนเพราะระบุสิ่งที่ต้องการ วิธีทำงาน และวิธีตรวจสอบผลลัพธ์ AI ช่วยร่างโค้ดได้ แต่ผู้พัฒนาต้องอ่าน ทดลอง และตรวจสอบโค้ดก่อนนำไปใช้งาน
